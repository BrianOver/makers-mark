## Orchestrator triage (2026-08-04)

**This is the first honest run.** Keep it as the baseline the next run is compared against.

### What it found that is REAL

- *"Day 1 Camp to day 1 ExpeditionDeep to day 1 Evening to day 2 Morning, with no progress made during
  these phases other than advances in time."* — the empty middle phases. Reached independently, from
  play, and it matches the structural verdict in
  `docs/plans/2026-08-03-001-feat-loop-structure-plan.md` (the player acts in one phase; the rest are
  bells to crank) and the owner's own "the base loop STILL is not complete". Two independent methods,
  same conclusion.
- It reported honestly that it never reached the forge, the counter, or the minigame, instead of
  inventing findings about them.

### Known limitation of THIS run, not of the game

The model can only press CONTROLS. Buildings are entered by clicking the world, so the town screen
offers it nothing but HUD/overlay buttons — it never got inside anything. That is why the run is
shallow, and it is the first thing to fix in the harness (give the bridge an `enter <venue>` verb, or
expose buildings in the control list).

### A fabrication incident worth remembering

The FIRST version of `tools/agent-playtest/prompts/judge.md` included real notes from the owner's
previous playtest as style samples. The model copied them back as its own observations — reporting
that it could not leave the forge and that the counter confused it, in a run where it entered neither.
Every one of those lines was a real bug from a *previous* build, which is exactly what made the output
so convincing.

The prompt now carries NO example findings and requires every finding to quote the log. If a future
run produces suspiciously familiar complaints, suspect this first.
